# 随机测试与方案探索报告

日期：2026-11-10。优化前基线：`0b5c2c0`；本轮版本：2.6.0。

## 测试设计

固定种子为 20261110、20261111、20261112，每个种子 73 组，共 219 组。包含随机生成的货物尺寸、种类、数量及重量，也包含重复运行的固定边界和已知装载容量样例。

| 测试类别 | 组数 |
| --- | ---: |
| 单件尺寸小于、等于、大于容器（含合法轴向旋转） | 72 |
| 规则网格货物数量低于、等于、超过容量 | 72 |
| 多种尺寸、同名不同规格、随机数量组合 | 24 |
| 超尺寸货物与可装货物混合 | 24 |
| 空清单、体积足够但形状不匹配、混合恰好铺满、超限 0.01cm | 12 |
| 45 件与 49 件固定基准 | 6 |
| 128、500、1000 件的数量边界 | 9 |
| 合计 | 219 |

总体积相等不代表几何可装。规则网格和专门构造的混合铺满样例有已知装载数量；一般随机组合只检查合法性和质量变化，不以未知最优值作为通过条件。

`tests/helpers/worker-runtime.cjs` 将生产代码实际生成的 Worker 源码放入 Node 真实线程执行，没有重写另一套装箱算法。`tests/helpers/random-cases.cjs` 独立计算边界、重叠和底部支撑，不调用生产校验函数作为唯一判断依据。还检查每件原货物只出现在“已装”和“未装”之一、原尺寸/重量/名称/颜色不变、输入坐标未被修改。

## 优化前后

首次使用种子 20261110 的 73 组测试：71 组通过，45 件和 49 件均触发 3 秒响应上限。不是装箱几何错误，而是已经出现完整解后仍等待全部线程。修复首次完整解立即完成、终止其他搜索，并将分层任务切小动态领取后，219/219 组通过。

额外修复：超尺寸物品直接归入未装清单，不再阻断可装物品或启动无意义的后台搜索；解的排序明确优先件数，再比较体积、堆高，避免体积权重掩盖漏装件数。

## 浏览器性能对照

同一台机器，Chrome 157.0.8103.39，浏览器报告 24 个逻辑核心。每种场景重复 3 次，以下为中位数；计时到布局与回放区域可用。所有测次均完整装入对应货物。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 45 件预设 | 4744ms | 61ms |
| 49 件基准 | 6846ms | 267ms |

这些是本机测量，不代表所有手机或 GPU 的速度。独立的“首个线程成功、其他线程不返回”回归测试，会验证结果及时返回且线程、计时器被清理。CI 的随机组合测试放宽到每组 10 秒，避免将共享 runner 的 CPU 争用误判为几何错误；浏览器和任务超时仍单独检查。

## 换方案效果

对 24 组混合货物分别继续搜索 3 次，共 72 次：全部返回了与上一方案不同的合法布局。布局身份忽略相同货物的 id 和数组排列，不能只换编号充当新方案。

本机该轮 24 组中有 7 组改善了既定质量指标。例如：

- 种子 20261111、`mixed-quantities-22`：从 15 件增加到 16 件，装载体积从 6819cm³ 增至 7329cm³。
- 种子 20261111、`mixed-quantities-14`：同为 11 件，装载体积从 19658cm³ 增至 23500cm³。
- 种子 20261112、`mixed-quantities-38`：同为 10 件且装载体积不变，堆高从 16cm 降到 11cm。

按钮会改变种子、物品顺序和分区顺序，并让贪心策略进入随机扰动试验。界面保留最佳结果，允许查看其他候选，也能恢复最佳。修改输入后最佳结果作废；取消或无新方案时保留原布局。单个盒子恰好占满容器的唯一布局会明确报告“未找到不同方案”，不会伪造变化。

种子能复现测试输入和随机扰动，但线程竞速与时间预算仍可能影响最终选中哪一个合法候选，不保证跨机器逐坐标一致。更换方案增加探索机会，不保证每次更好，也不证明全局最优。

## 复现和 CI

```sh
npm test
npm run test:random
npm run check
npm run test:browser
```

`PACKING_TEST_SEED` 指定单个随机种子；`PACKING_TEST_REPORT` 指定 JSON 输出路径。默认随机测试不需要 npm 安装或 Chrome。浏览器测试使用已有 Chrome 和 Puppeteer，见 README。

GitHub Actions 运行单元、随机组合和浏览器检查，并上传 `randomized-packing-report`。这份报告中的性能和改善案例来自本机测量，CI 不强求随机搜索一定重复相同的改善数量。

未验证真实手机触控和实际运输稳定性；支撑比仅为几何规则。
