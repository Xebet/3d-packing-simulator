# 优化与复查记录

日期：2026-11-10。基线：`bc49173`。范围：单用户浏览器中的离线装箱工作台，清单合计不超过 1,000 件。

## Ponytail audit

What this repo does: 用户配置容器和货物，运行几何装箱搜索或手动排布，在三维视口查看布局、支撑、体积和重量。计算与数据均留在浏览器中。

### Must fix

1. 极小尺寸会生成过多层。
   - What this is: `Packer.getPartitions` 为分层回溯分配数量。
   - Problem: 深度 500、公共尺寸 0.01 会产生 50,000 层；原实现会在主线程预生成分区，结果数量上限也没有停止全部递归路径。
   - Fix: 分区生成全部移入 Worker；限制层数、件数、访问节点和搜索时间，超出范围使用贪心策略。
   - If we skip it: 输入合法仍可能导致页面长时间无响应或递归溢出。

2. 计算缺少统一的生命周期。
   - What this is: 原 `app.js` 创建多个 Worker 后通过回调更新布局。
   - Problem: 无法取消，创建 Worker 抛错时可能遗留加载状态；旧任务也可能覆盖更新后的配置。
   - Fix: `packing-jobs.js` 统一管理任务、超时、终止和 AbortSignal；失败保留旧布局，回退明确显示为基础搜索。
   - If we skip it: 用户被困在进度弹窗，或看到已经失效的结果。

3. 校验不完整，接近但不同的尺寸被视为公共尺寸。
   - What this is: 几何校验负责接收算法和线程返回的布局。
   - Problem: NaN 容器尺寸、重复 id、缺失物品未完整拒绝；0.1 的公共尺寸容差可能让层偏移与实际盒深不一致。
   - Fix: 严格校验容器、几何、id 和 Worker 旋转尺寸；统一公共尺寸与碰撞容差；分层结果也执行完整校验。
   - If we skip it: 无效布局可能被接受或物品重复显示。

4. 重量和清单上限存在边界错误。
   - What this is: 统计和配载功能读取重量、数量及最少数量。
   - Problem: 空箱重量 0 被 `|| 1.5` 覆盖；每个产品各允许 1,000 件，清单合计无上限；最少数量可在分配开始前就超过总量限制。
   - Fix: `cargo.js` 提供可测试的边界校验与纯分配函数；比例与最少数量可以共存，无法放入的产品不参与比例分配。
   - If we skip it: 重量不准确，数量过大，配载估算与真实几何不一致。

5. 手动布局状态不一致，模式切换丢失操作。
   - What this is: 手动选择、删除和模式切换共同管理布局。
   - Problem: 删除下层盒子不检查上层支撑；取消选择可重置错误颜色；切换模式清空对应布局。
   - Fix: 复用完整布局校验；删除、位移和旋转后更新状态；保留两套模式布局，并为删除与移出提供 10 秒撤销。
   - If we skip it: 错误布局看似有效，用户需要重新排布。

6. 弹窗内容与键盘焦点不受统一控制。
   - What this is: 错误消息通过 innerHTML 展示，弹窗仅把初始焦点移入。
   - Problem: 任意错误文本可被解释为 HTML；Tab 可以移动到弹窗后的控件。
   - Fix: 转义消息，仅处理受限的加粗格式；所有产品名称转义、颜色严格校验；增加 CSP、背景 inert、焦点循环和焦点恢复。
   - If we skip it: 将来接入外部错误文本会扩大注入面，键盘用户也难以操作。

### Should fix

7. 静止场景仍不断执行控制器更新。
   - What this is: 原渲染循环每帧调用 requestAnimationFrame 和 OrbitControls.update。
   - Problem: 即使没有变化，也持续运行更新逻辑。
   - Fix: 使用控制器 change 和显式场景更新触发绘制；阻尼停止后不再调度；隐藏页面暂停播放，ResizeObserver 跟踪真实视口尺寸，大清单关闭实时阴影。
   - If we skip it: 空闲 CPU 和电池开销持续存在。

8. 界面遮挡、对比度与窄屏操作问题。
   - What this is: 原界面使用渐变、玻璃面板、固定悬浮统计和自动弹出导览。
   - Problem: Hallmark 基线记录 124 个 Floor 问题和 4 个 Reflex 问题，包含低对比文字、窄屏控件换行和缺少图标语义。
   - Fix: Console 应用工作台、日夜主题令牌、单色状态、可展开录入与移动端配置；保留原输入与脚本查询入口，导览按需打开。
   - If we skip it: 小屏配置与键盘操作更困难，工作区也可能被遮住。

9. 候选放置逻辑重复，空腔适配重复遍历同规格物品。
   - What this is: 贪心算法分别实现前瞻窗口内与窗口外的候选搜索。
   - Problem: 两处几何和支撑规则必须同步维护；适配检查还会对同规格货物重复计算。
   - Fix: 合并候选循环并保留原前瞻语义；空腔适配只检查唯一规格。
   - If we skip it: 后续修复容易只改一处，重复规格清单也有额外开销。

Verdict: 上述问题均已落实修复。保持原生前端结构，没有增加运行时依赖或框架。

## 使用限制

装箱是有预算的启发式搜索，不保证全局最优。大清单或 Worker 不可用时，布局质量可能下降。承载上限用于配载数量分配和超重提示，几何装箱不会自动减少超重货物。支撑比不替代实际重心、箱体强度或运输安全验证。
